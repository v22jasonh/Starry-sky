# 中国金融官方文件检索、效力分析与合同审核

## 目标

把中国金融业务相关的公开官方法律规范视为动态语料库，并将其用于交易分析和合同审核。对具体任务完成：

1. 找到可核验的官方原文；
2. 核对文件身份、文号、机关、日期和效力层级；
3. 判断现行有效、修改、部分失效、废止、未施行或征求意见等状态；
4. 回溯机构改革前的历史文件并判断承继关系；
5. 把实体法、程序法、金融监管、财政税务及地方规则按同一业务事实链衔接分析；
6. 对合同进行结构、条款、风险分配、可执行性和证据链审核；
7. 输出可追溯的依据、风险分级、修改建议和谈判底线。

## 何时读取参考文件

- 涉及具体官方机关、历史机构、官方数据库或检索优先级时，读取 `references/SOURCE_MATRIX.md`。
- 涉及跨法域问题、公司/破产/执行/刑事/税务/数据/国资/跨境等衔接时，读取 `references/LEGAL_COVERAGE_MATRIX.md`。
- 需要逐项核验文件身份和效力时，读取 `references/VALIDATION_CHECKLIST.md`。
- 需要审核、修改、起草合同或识别合同红线时，读取 `references/CONTRACT_REVIEW_METHODOLOGY.md`；逐项扫描时再读取 `references/CONTRACT_REVIEW_CHECKLIST.md`。
- 需要固定输出格式时，读取 `references/OUTPUT_TEMPLATES.md`。
- 需要理解典型调用方式时，读取 `examples/README.md`。

不要在任务开始时无差别加载全部参考文件；只按当前问题需要加载。

## 核心原则

### 1. 官方原文优先

优先级原则：

1. 原发文机关官方网站、官方公报、正式附件/PDF；
2. 国家级官方法律法规库、国务院政策文件库、最高法公报等官方汇总源；
3. 联合发文机关或其他国家机关的完整官方转载；
4. 省级法院、税务、金融管理、市场监管等地方官方门户；
5. 商业数据库、律所文章、媒体、论坛等仅用于发现线索，不得作为关键结论的唯一依据。

### 2. 文件身份与效力分开核验

网页能打开不等于文件现行有效。关键文件至少检查文件全称、文号、发文机关、成文/公布/施行日期、效力层级、适用地域和对象、后续修改/废止/替代文件，以及上位法变化。

### 3. 区分文件类型

不得仅凭标题中的“规定、办法、意见、通知”判断效力。应识别法律、行政法规、司法解释、部门规章、行政规范性文件、司法政策文件、批复、会议纪要、指导性案例、典型案例、政策解读、征求意见稿或行业自律规则。

### 4. 历史机构不等于历史文件失效

机构撤销或合并不当然使原文件失效。涉及银监会、保监会、银保监会及其他机构改革时，必须同时核验承继机关、后续清理决定、修改或替代规则、新上位法变化。

### 5. 时间轴优先

对跨越重要修法节点的业务，先建立法律事实时间轴，再确定适用版本。预置提醒包括：

- 2021-01-01：民法典施行；
- 2024-07-01：新公司法施行；
- 2025-01-01：新反洗钱法施行；
- 2025-05-20：民营经济促进法施行；
- 2025-10-15：修订反不正当竞争法施行；
- 2026-01-01：增值税法施行、修改后的网络安全法施行；
- 2026-03-01：新修订仲裁法施行。

这些日期只是提醒。每次实际分析仍必须检查截至检索日是否有新的修改、解释或废止决定。

## 标准法律检索工作流

### 第一步：拆分事实

识别主体、交易/行为、债权或金融产品性质、时间点、地域和管辖，以及是否进入仲裁、诉讼、执行、破产，是否涉及税务、会计、监管、刑事、数据或国资。

### 第二步：建立法域路由

默认扫描：民法典/合同担保 → 公司责任 → 金融监管 → 税务会计 → 争议解决 → 财产保全 → 强制执行 → 执行异议 → 破产 → 刑事 → 数据/个人信息 → 行政监管 → 地方规则。

事实触发清单外法域时必须继续扩展。详细最低覆盖面见 `references/LEGAL_COVERAGE_MATRIX.md`。

### 第三步：上位法和最新正式规范优先

先查法律、行政法规和司法解释，再查部门规章、规范性文件、地方规则和实务口径。征求意见稿、新闻稿、政策解读不得替代正式规范。

### 第四步：定向检索

按“机关 + 文件名/业务关键词 + 文号 + 年份 + 历史机构名称”组合检索。需要来源路由时读取 `references/SOURCE_MATRIX.md`。

### 第五步：效力交叉核验

关键文件尽量由两个官方渠道确认身份或效力；无法交叉确认时明确标注证据缺口，不得把推断写成“现行有效”。

### 第六步：冲突与衔接分析

至少判断上位法与下位法、新法与旧法、一般规定与特别规定、司法解释与监管规则各自解决的问题、地方规则是否超越授权，以及会计核销、税务损失确认与实体债权消灭是否被错误混同。

### 第七步：形成结论

结论必须能回溯到：事实 → 法律关系 → 规范依据 → 效力状态 → 适用分析 → 风险/不确定性。

## 专业合同审核工作流

收到“审核合同、审协议、修改合同、找风险、给红线意见、出谈判建议”等任务时，优先进入合同审核模式。

### 第一步：明确审核立场和交易目标

确认我方身份、合同目的、已达成商业条件、不可谈判事项、风险偏好和审核目标。没有立场的审核只会产生大量无效修改。

### 第二步：先重建交易，不要从第一条开始逐字改

至少建立：主体图、资金流、资产/权利流、担保/增信关系、履行时间轴、主从合同关系和争议救济路径。

### 第三步：按四层框架审核

1. **交易与法律结构**：交易是否有效、主体和授权是否合格；
2. **合同结构与完整性**：不仅找错误条款，还要找缺失条款；
3. **风险分配与谈判位置**：判断风险由谁控制、谁承担、是否与收益匹配；
4. **履约、证据与争议执行**：检查条款能否被业务执行、被证据证明、被法院/仲裁机构执行。

### 第四步：对重要条款使用“五问法”

1. 谁承担义务/享有权利；
2. 做什么；
3. 何时或何种条件下触发；
4. 如何证明；
5. 不履行怎么办。

### 第五步：区分四类风险

- **A类：法律/效力风险**；
- **B类：重大商业风险**；
- **C类：履约和运营风险**；
- **D类：文本和一致性风险**。

不得把纯商业谈判事项伪装成“法律强制要求”。

### 第六步：风险分级

- **Critical / 红色**：可能导致交易违法、核心条款无效、重大资金损失、无法取得核心权利或重大监管/刑事风险；原则上签署前必须解决；
- **High / 橙色**：可能造成显著经济损失、核心履约障碍或严重争议劣势；强烈建议修改；
- **Medium / 黄色**：可管理但需要业务确认、流程控制或谈判优化；
- **Low / 蓝色**：文字、定义、一致性和低影响问题。

### 第七步：给出可操作的修改意见

每个重大问题尽量同时给出：原条款定位、风险类型、风险等级、原因、法律/商业依据、建议修订文本、谈判底线，以及无法修改时的替代控制措施。

### 第八步：数字、期限和公式必须独立复核

本金/价款、利率、罚息、违约金、费用、税费、期限、通知期、责任上限、担保金额、分期合计和公式变量必须核算。不得受合同原数字锚定而跳过复算。

### 第九步：跨文件一致性审核

金融交易常由主协议、借款、担保、债权转让、资产清单、账户监管、授权、交割文件组成。必须横向核对主体、金额、标的、日期、利率、担保范围、优先顺位、通知地址、定义和文件优先顺序。

完整方法论见 `references/CONTRACT_REVIEW_METHODOLOGY.md`，逐项条款清单见 `references/CONTRACT_REVIEW_CHECKLIST.md`。

## 金融债权处置强制联动

涉及不良贷款、债权转让、担保、SPV、终本恢复、变更追加被执行人、冻结扣划、核销出表、执转破等事项时，默认沿以下链条核验：

**民法典实体权利 → 公司/主体责任 → 仲裁或民事诉讼取得执行依据 → 强制执行 → 执行异议/追加当事人 → 企业破产/集体清偿 → 金融监管 → 财政/会计 → 税务处理。**

特别注意：

- 实体法上的债务加入、代偿、股东责任或关联关系，不当然构成执行程序中直接追加被执行人的依据；
- “终结本次执行”不等于债权消灭；
- 查封、冻结等控制措施不等于最终受偿权；
- 会计核销/税务损失确认不等于实体债权消灭；
- 批量债权不得仅因商业上成包就推定可共用一个执行依据、执行案号或追加路径。

## 金融合同专项审核

对以下合同默认加载合同审核方法论并结合相应法律覆盖矩阵：

- 借款/授信合同；
- 保证、抵押、质押和其他增信文件；
- 债权转让、不良资产转让协议；
- SPV、资产管理、催收服务协议；
- 债务重组、和解、展期协议；
- 保理、融资租赁、票据、应收账款融资；
- 账户监管、资金归集、回款分配协议。

必须同时检查合同条款与实际诉讼、仲裁、执行、破产路径是否一致。

## 法院文件特别规则

必须区分司法解释、批复、会议纪要、司法政策文件、指导性案例、典型案例、地方高院审判指引和内部工作规则。不得把地方高院工作意见描述成全国普遍适用的司法解释。

## 输出要求

根据用户任务选择 `references/OUTPUT_TEMPLATES.md` 中的格式。

法律/文件任务默认：先结论，再依据；列明关键文件名称、文号、机关、日期、层级、状态和官方来源；区分规范要求、司法规则、监管口径和实务做法。

合同审核任务默认输出：执行摘要 → 交易结构 → 红色/橙色风险 → 逐条修改建议 → 缺失条款 → 业务待确认事项 → 签署前条件 → 谈判底线 → 总体风险等级。

## 禁止事项

- 不编造文件名、文号、条文、发布日期或效力状态；
- 不只根据搜索摘要引用规范；
- 不把征求意见稿当现行法；
- 不把政策解读或新闻稿当规范性文件；
- 不因机构撤销直接认定旧文件失效；
- 不把行业协会规则写成国家行政规章；
- 不把“对我方不利”直接等同于“违法无效”；
- 不只改文字而忽略交易结构、履约流程和证据链；
- 不在未核验执行依据、管辖、当事人适格和法定程序前直接得出批量强制执行可行结论。

## 最终质量检查

提交答案前确认：

1. 是否找到了最权威的官方原文；
2. 是否核验了修订、废止和施行状态；
3. 是否检查了法律事实时间轴；
4. 是否扫描了可能衔接的法域；
5. 合同审核时是否先理解了交易结构和我方立场；
6. 是否同时检查了错误条款和缺失条款；
7. 是否把法律风险、商业风险、运营风险和文本风险分开；
8. 是否复核了关键金额、期限、利率和计算公式；
9. 是否明确证据缺口和需要业务确认的事实；
10. 是否对关键结论给出置信度：高 / 中 / 低 / 未知。
