# 中国金融官方文件检索与效力分析

## 目标

把中国金融业务相关的公开官方法律规范视为动态语料库，而不是静态法规清单。对具体问题完成：

1. 找到可核验的官方原文；
2. 核对文件身份、文号、机关、日期和效力层级；
3. 判断现行有效、修改、部分失效、废止、未施行或征求意见等状态；
4. 回溯机构改革前的历史文件并判断承继关系；
5. 把实体法、程序法、金融监管、财政税务及地方规则按同一业务事实链衔接分析；
6. 输出可追溯的依据、适用结论、冲突关系和不确定事项。

## 何时读取参考文件

- 涉及具体官方机关、历史机构、官方数据库或检索优先级时，读取 `references/SOURCE_MATRIX.md`。
- 涉及跨法域问题、公司/破产/执行/刑事/税务/数据/国资/跨境等衔接时，读取 `references/LEGAL_COVERAGE_MATRIX.md`。
- 需要逐项核验文件身份和效力时，读取 `references/VALIDATION_CHECKLIST.md`。
- 需要固定输出格式时，读取 `references/OUTPUT_TEMPLATES.md`。
- 需要理解典型调用方式时，读取 `examples/README.md`。

不要在任务开始时无差别加载全部参考文件；只按当前问题需要加载。

## 核心原则

### 1. 官方原文优先

优先级原则：

1. 原发文机关官方网站、官方公报、正式附件/PDF；
2. 国家级官方法律法规库、国务院政策文件库、最高法公报等官方汇总源；
3. 联合发文机关或其他国家机关的完整官方转载；
4. 省级法院、税务、金融管理、市场监管等地方官方门户；
5. 商业数据库、律所文章、媒体、论坛等仅用于发现线索，不得作为关键结论的唯一依据。

### 2. 文件身份与效力分开核验

网页能打开不等于文件现行有效。关键文件至少检查：

- 文件全称和文号；
- 发文/联合发文机关；
- 成文、公布、施行日期；
- 法律效力层级；
- 适用地域和对象；
- 后续修改、废止、清理、替代文件；
- 官方法规库的效力状态字段；
- 上位法变化是否造成冲突。

### 3. 区分文件类型

不得仅凭标题中的“规定、办法、意见、通知”判断效力。应识别其实际类型，例如：法律、行政法规、司法解释、部门规章、行政规范性文件、司法规范性文件/司法政策文件、批复、会议纪要、指导性案例、典型案例、政策解读、征求意见稿或行业自律规则。

### 4. 历史机构不等于历史文件失效

机构撤销或合并不当然使原文件失效。涉及银监会、保监会、银保监会及其他机构改革时，必须同时核验：机构沿革、承继机关、后续清理决定、修改或替代规则、新上位法是否改变原规范基础。

### 5. 时间轴优先

对跨越重要修法节点的业务，先建立法律事实时间轴，再确定适用版本。尤其注意：

- 2021-01-01：民法典施行；
- 2024-07-01：新公司法施行；
- 2025-01-01：新反洗钱法施行；
- 2025-05-20：民营经济促进法施行；
- 2025-10-15：修订反不正当竞争法施行；
- 2026-01-01：增值税法施行、修改后的网络安全法施行；
- 2026-03-01：新修订仲裁法施行。

这些日期只是预置提醒。每次实际分析仍必须检查截至检索日是否有新的修改、解释或废止决定。

## 标准工作流

### 第一步：拆分事实

至少识别：主体及其法律身份；交易/行为；债权、金融产品或资产性质；时间点及持续期间；地域和管辖；是否已进入仲裁、诉讼、执行、破产；是否涉及税务、会计、监管、刑事、数据或国资问题。

### 第二步：建立法域路由

先扫描：民法典/合同担保 → 公司责任 → 金融监管 → 税务会计 → 争议解决 → 财产保全 → 强制执行 → 执行异议 → 破产 → 刑事 → 数据/个人信息 → 行政监管 → 地方规则。

事实触发清单外法域时必须继续扩展，不得被预置列表限制。详细最低覆盖面见 `references/LEGAL_COVERAGE_MATRIX.md`。

### 第三步：上位法和最新正式规范优先

按适用问题先查法律、行政法规和司法解释，再查部门规章、规范性文件、地方规则和实务口径。征求意见稿、新闻稿、政策解读不得替代正式规范。

### 第四步：定向检索

按“机关 + 文件名/业务关键词 + 文号 + 年份 + 历史机构名称”组合检索。需要来源路由时读取 `references/SOURCE_MATRIX.md`。

### 第五步：效力交叉核验

关键文件尽量由两个官方渠道确认身份或效力；无法交叉确认时明确标注证据缺口，不得把推断写成“现行有效”。

### 第六步：冲突与衔接分析

至少判断：上位法与下位法；新法与旧法；一般规定与特别规定；司法解释与行政监管规则各自解决的法律问题；地方规则是否超越授权；内部工作文件能否对外设定义务；会计核销、税务损失确认与实体债权消灭是否被错误混同。

### 第七步：形成结论

结论必须能回溯到：事实 → 法律关系 → 规范依据 → 效力状态 → 适用分析 → 风险/不确定性。

## 金融债权处置强制联动

涉及不良贷款、债权转让、担保、SPV、终本恢复、变更追加被执行人、冻结扣划、核销出表、执转破等事项时，默认沿以下链条核验：

**民法典实体权利 → 公司/主体责任 → 仲裁或民事诉讼取得执行依据 → 强制执行 → 执行异议/追加当事人 → 企业破产/集体清偿 → 金融监管 → 财政/会计 → 税务处理。**

特别注意：

- 实体法上的债务加入、代偿、股东责任或关联关系，不当然构成执行程序中直接追加被执行人的依据；
- “终结本次执行”不等于债权消灭；
- 查封、冻结等控制措施不等于最终受偿权；
- 会计核销/税务损失确认不等于实体债权消灭；
- 批量债权不得仅因商业上成包就推定可共用一个执行依据、执行案号或追加路径。

## 法院文件特别规则

必须区分司法解释、批复、会议纪要、司法政策文件、指导性案例、典型案例、地方高院审判指引和内部工作规则。不得把地方高院工作意见描述成全国普遍适用的司法解释。

## 输出要求

根据用户任务选择 `references/OUTPUT_TEMPLATES.md` 中的格式。默认要求：

- 先给结论，再给依据；
- 关键文件列明文件名、文号、机关、日期、效力层级、当前状态和官方来源；
- 分清“规范要求”“司法裁判规则”“监管口径”“实务做法”；
- 历史案件明确适用版本；
- 找不到官方原文或效力无法确认时直说；
- 用户要求“全部文件”时表述为“截至检索日已核验的官方公开文件集合”，不得宣称绝对穷尽。

## 禁止事项

- 不编造文件名、文号、条文、发布日期或效力状态；
- 不只根据搜索摘要引用规范；
- 不把征求意见稿当现行法；
- 不把政策解读或新闻稿当规范性文件；
- 不因机构撤销直接认定旧文件失效；
- 不把行业协会规则写成国家行政规章；
- 不在未核验执行依据、管辖、当事人适格和法定程序前直接得出批量强制执行可行的结论。

## 最终质量检查

提交答案前确认：

1. 是否找到了最权威的官方原文；
2. 是否核验了修订、废止和施行状态；
3. 是否检查了法律事实时间轴；
4. 是否扫描了可能衔接的法域；
5. 是否把实体权利、程序权利、监管要求和账税处理分开；
6. 是否明确了证据缺口；
7. 是否对关键结论给出置信度：高 / 中 / 低 / 未知。
